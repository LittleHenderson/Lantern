How it works

Add your app

Drop a folder or paste a GitHub link. Lantern reads your code the way a senior engineer reads a pull request, so nothing can go wrong on your machine and nothing leaves it.

2

Lantern maps every path a visitor can take

From a click in the browser to the line on your server that handles it, every hop drawn and every call checked for problems.

Each problem in plain words, ranked by whether a visitor can reach it. When it's gone, an evidence packet pinned to your commit says so.

Your code, your choice

Best for privacy: download it and run it on your computer

Everything Lantern does by itself (the map of your app, the security findings, the readiness grade, the evidence report) runs on your own machine. No account, no upload, no server of ours ever sees your code. This is the recommended way to use Lantern, and the only way we can promise that nothing leaves your computer.

  1. Install Python 3.11 or newer from python.org (on Windows, tick "Add python.exe to PATH").
  2. Install Lantern in a terminal (PowerShell on Windows, Terminal on Mac):
    $ pip install "lantern[scan] @ git+https://github.com/LittleHenderson/Lantern"
  3. Open it:
    $ lantern serve
    Your browser opens Lantern at a local address (127.0.0.1) that only your computer can reach.
  4. Add your app: Browse… to its folder, or paste a GitHub link. A link is cloned onto your computer, not onto a server, and analyzed there.

Model explanations are off until you turn them on. With a key or a sign-in set up, Lantern still asks you once, and tells you what will be sent, before any code leaves the machine.

Optional, at your own risk: anything that uses an outside model

Two features talk to a model provider on the internet, and only if you switch them on:

  • Plain-word explanations. The function being explained (its code, and the names of what calls it and what it calls) is sent to the provider you chose: Anthropic through the free allowance, DeepSeek, Anthropic or an OpenAI-compatible service with your own key, or a model running on your own machine (Ollama, LM Studio), which sends nothing anywhere.
  • Ask Lantern. Your question, plus the project's results that the answer needs (finding titles, file names and line numbers, readiness checks, the selected function's explanation), goes to the same provider. A screenshot you drop in is read on your computer; the picture itself is not uploaded.

What that provider does with the text is governed by its own terms, not by Lantern. The free allowance goes through a small gateway we run; it keeps a count of requests per account and never stores code or prompts, but it is still a server on the internet between you and the model. If your code is confidential, use a local model or leave explanations off: every finding, path and grade works without them.

There is no cloud version of Lantern that holds your repository. The "live example" on this site is a sample report built from a demo app, not a place to upload yours.

What Lantern promises

Facts from tools, words from models

Every path, link and finding comes from code that reads your code. A model only explains; it never invents, hides or closes a finding.

Shows its confidence

Every connection says how sure Lantern is (seen · resolved · likely · possible) and how it was found. What it could not follow is counted, not guessed.

Your code stays yours

Analysis runs on your computer. Nothing is uploaded unless you turn on explanations, and then only the pieces being explained, after you say yes.

Proof you can hand over

An evidence report pinned to a commit, with what was checked, what was found, what was fixed, and the limits, in words a skeptical engineer accepts.
